# Text v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a built-in `Text` type to Waxwing: literals with escapes and
`${…}` interpolation, raw (`#"…"#`) and multiline (`"""`) forms, `++`,
code-point comparison, raw-alone/quoted-nested printing, and a built-in
`show`.

**Architecture:** A new lexer module decodes every text literal into a
flat token sequence (open, chunks, holes, close), which the parser turns
into literal, interpolation and `++` nodes. `TText` is added to every type
representation, the checker types the new nodes, and Go lowering maps Text
to `string` and reuses the declared-type printers for `show`. A behavior-
preserving split of `Domain/Type.purs` comes first. Invalid UTF-8 is caught
in the Runtime file read.

**Tech Stack:** PureScript 0.15.16, Spago 1.0.4, purs-tidy 0.11.1, Node test
runner, Go 1.26.4. No new dependency (pure layers may use
Data.String.CodePoints; Data.Char and Data.Enum are not allowed).

**Spec:** docs/plans/2026-10-13-text-design.md, including its "Plan-time
amendments". "§n" below refers to its sections.

## Global Constraints

- AGENTS.md governs. Files are at most 250 physical lines and 80 columns
  (counted in code points). Use `where`, never `let … in`. No anonymous
  lambdas. Use `maybe`/`either` with named helpers. Use purs-tidy Unicode
  punctuation. Respect the layer and IR-boundary allowlists
  (scripts/structure.mjs). No `unsafe`, `Partial` or `fromJust` text in
  .purs files, and no `.skip(`/`.only(` anywhere.
- The six snapshots bootstrap/{answer,functions,lists,services,shapes,
  tree}.go stay byte-identical. A program without Text emits today's Go.
  New Go helpers and imports are emitted only when used.
- Locations are half-open UTF-16 code-unit offsets with one-based
  line/column (§2). A non-BMP character counts as 2.
- Error texts are exactly those of §6 (E_SYNTAX via `Syntax "<text>"`).
  Type errors reuse `Expected Text, found <t>` and `Expected a printable
  value, found <t>`. Any other new user-facing text needs the user's
  approval. Stop and report rather than inventing text.
- Text compares by code point (U+1F600 > U+FFFD) in Go and in the
  reference interpreter.
- `show(t)` of a Text is `t`, unquoted. `print` and `main`'s printed result
  end with one newline, and `show` adds none. A Text nested in data prints
  quoted with canonical escaping: `\"`, `\\`, `\n`, `\t`, `\r`, and `\${`
  for every `${`; a lone `$` stays literal. Exactly U+0000–001F and
  U+007F–009F (other than `\n \t \r`), U+2028–2029 and the bidi controls
  U+202A–202E and U+2066–2069 are written `\u{…}` in lowercase hex; every
  other scalar is raw. The set is fixed so it is stable across Unicode
  versions and matches the JS interpreter; the bidi controls are there
  because of Trojan Source. The quoted form
  reads back to the same text.
- `++` sits at `+`'s precedence, left-associative, mixable with `+` in one
  chain, and bounded by the existing nesting limit (129 operands compile,
  130 give E_NESTING).
- Every task: each new behavioral test is seen failing before its code.
  `rm -rf output && GOTOOLCHAIN=go1.26.4 npm run verify` exits 0. No
  raised bound, no rerun hiding a failure. Run `node scripts/differential.mjs
  --baseline <build of the task's base>` (see docs/engineering.md). The
  only differences allowed are the new Text sources, plus amendment 5's
  E_LEX span. Commit on the plan's branch and never push. Agent copies
  exclude .build and are deleted afterwards. Delete .build/regression
  after proofs.

## Review Focus

1. **Text in failures and the defect report.** `fail` with a Text payload,
   `crash("a\nb")`, and Text inside a `Fail(E)` family's constructor. The
   defect report keeps its one-cause-per-line format (`crash: a\nb`), and a
   Text payload's runtime Fail key must not collide with any existing key.
   Int is -1, Bool -2, Unit -3 and data is -4-id, so no free key is
   adjacent. Pick one outside the data range (for example math.MinInt32),
   changing no existing key, and record it in ADR 011. Owned by Task 3.
2. **Braces and quotes inside holes.** `"${ { let x = "}"; x } }"`,
   `"${h(handler L { l() => "}" })}"`, and a hole spanning lines in a
   `"""` block. Owned by Task 5.
3. **Non-BMP text everywhere.** A U+1F600 literal before an error (span
   arithmetic), a non-BMP character in a nested printed value, comparison
   against U+FFFD, and an E_LEX non-BMP character outside a literal
   (2-unit span). Owned by Tasks 2-3.
4. **Text in generic and effectful positions.** `List(Text)` and
   `Box(Text)` via specialization, a Text operation argument and result
   through a handler, `defer print(t)`, and an effectful hole inside a
   `defer`. Owned by Tasks 3 and 5.
5. **Large literals in Go.** A 1 MB literal and a literal of only escapes
   emit a canonical Go literal that `go build` accepts, deterministically.
   Owned by Task 9.

## Execution

- **Method and roles** (user direction 2026-10-10 and 2026-10-13):
  subagent-driven. A Sonnet implementer does each task and an Opus
  reviewer reviews each task. The controller escalates to Opus on a
  genuine ambiguity, a gate failure or a second failed review.
- **Branch:** `text`, in the worktree `.worktrees/text`, branched from
  `main`. It integrates into main by fast-forward only, with no merge
  commits, and never pushes without the user's approval.
- **Review gates.** Each is a stop: the next task does not start until the
  gate passes.
  1. **After Task 1**, the behaviour-preserving split. The Opus review
     confirms there is no behaviour change, using the differential with 0
     differences and an unchanged test count.
  2. **After every later task**, the task review covers spec compliance and
     quality.
  3. **Before final acceptance**, a whole-branch Opus review.
- **Findings at every gate.** Critical and Important findings are fixed,
  the affected tests, verify and the differential are rerun, and a scoped
  re-review confirms the fix. Minor findings go to the ledger and the
  whole-branch review triages them. Integration needs the whole-branch
  review's approval and then the user's decision.

    - CRLF source equals LF source.
    - No final newline, unless the source has a blank line before the
      closing `"""`.
    - `"""x` → `""" must be followed by a line break`.
    - `x"""` on the last line → `The closing """ must be on its own line`.
    - Interpolation and escapes work in blocks, `#"""…"""#` makes them
      raw, and a hole may span lines.
