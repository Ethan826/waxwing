> superpowers:subagent-driven-development (recommended) or

**Status: a plan only. Not authorized for implementation.** Dossier
§18.69: "The implementation plan may now be written. Implementation
and proof work stay separately unauthorized." Nothing below has been
run. Each task waits for the author's authorization of the plan, and
the tasks marked **gated** also wait for the decision gate they name
(§3). Proof work appears only as a dependency (§4); no task in this
plan proves anything.

**Goal:** replace today's single `Either Diagnostic` checking chain
with R0's pipeline. Each declaration's complete constraint problem is
generated by syntax-directed rules. A `decide` stage then combines
injected strategies, rules and refuters into a verdict (Solved,
Contradiction or Unresolved) or an internal fault, and admission
and the ground re-check sit between the verdict and lowering.

**Architecture:** T-R0a's pipeline (generation-interface.md §2):
`generate` and `staticRules` per declaration, `decide` over the
complete `RecordedProblem`, then program-wide `admit`, specialization
of admitted declarations only, and the ground re-check per reached key
before Go emission. Today's online solver becomes one search strategy
(`online`), whose candidate a new trusted check (`checkSubstitution`,
G0) must accept before it counts.

**Tech Stack:** PureScript 0.15.16, Spago 1.0.4, purs-tidy 0.11.1,
Node ≥22.5 test runner (`node --test`), Go 1.26.4 for emitted code.

## Global Constraints

- AGENTS.md applies to every task: Domain, Features and Format stay
  pure; imports run only to the same or an earlier layer; expected
  semantic failures are `Either`; error codes are an ADT.
- Only Features.Check* and Features.Specialize* import
  Domain.Checked.Internal. Only Features.Specialize*, Format.Go* and
  Domain.IR.Parts import Domain.IR.Internal (scripts/structure.mjs:26-31).
- Maintained source, tests and tooling: at most 250 physical lines per
  file, about 100 as a target; declarations aim at 30 lines, 3 nested
  decisions, 8 branches, 8 `where` bindings.
- `where`, never `let … in`; no anonymous lambdas passed to
  map/traverse; `maybe`/`maybe'`/`either` with named helpers.
- Every .md, .mjs, .js and .wxw line at most 80 code points
  (`node scripts/width.mjs`).
- Inject implementations, never select by flag (the author's
  standing rule; T-R0a G-inject). Strategies, refuters, rules,
  budgets, admission rules and the forcedness policy are values
  passed in from `Program.Compile`.
- No catch-all where a failure becomes a semantic claim
  (docs/engineering.md "Result boundary classification"); each
  classifier is tested with every constructor injected directly.
- A regression test is shown failing with its defect restored, in an
  isolated copy: a row in scripts/regression-r0.mjs (registered in
  scripts/regression.mjs), with its probe in test/regression-r0.mjs.
- Unresolved texts never say the program is wrong and never assert a
  number of solutions; Unresolved fixtures cover zero, one and
  several solutions (docs/engineering.md:562-565).
- A diagnostic that names a culprit states its evidence (the
  author's rule "blame needs evidence"); Contradiction blame cites
  premise sources.
- Keep today's diagnostics until the step that changes them lands.
  Every changed fixture is listed in that task's commit.
- Stage explicit paths only (`git add <file> …`, never a directory).
  No merge commits; integrate by fast-forward or rebase. No push.
- `npm run verify` passes at the end of every task.

## Review Focus

These five input classes are implied by the spec and the most likely
to hurt a user, but no single AT/RT test exercises them. Each line
names the test that pins it and the task that owns it.

1. **Ordinary programs that use handlers, `fail`, effect arguments or
   `Option(a)`-like data.** Under the conservative boundary (§18.69
   Q3) every such declaration carries an `outside` marker and cannot
   be Solved (T-R0b §11 item 4). Expected: no program compiled today
   stops compiling without the author choosing it. Pinned by the
   census in Task 3.5 and the window table in Task 4.6.
2. **A file with several broken declarations.** Today the first
   `Left` hides the rest (Check.purs:22). Expected: every
   declaration reported once, in declaration order, with the first
   diagnostic unchanged. Pinned in Task 1.2
   (`reports each broken declaration once, in order`).
3. **A recursive component with one Unresolved member.** Expected:
   the others stay Solved, and the text names the blocking member.
   Pinned in Task 6.1 (`ComponentBlocked names the member`).
4. **`main` returning a declared type whose constructors may hold a
   function**, judged by the printability atom Sig10 always records.
   Expected: today's verdict (Check.purs:56-67) kept. Pinned in Task
   4.2 (`main's printability atom agrees with printableEntry`).
5. **Large programs**: generation, `decide` and the always-on
   re-check add work on every declaration and every key. Expected:
   the existing timing suites (`*.serial.test.mjs`) still pass within
   their bounds. Pinned in Tasks 3.5 and 6.4 (cost measured on the
   scale programs).

## 8. Problems in the R0 documents found while planning

1. **The conservative boundary conflicts with "keep today's
   diagnostics."**
   §18.69 Q3 keeps every `outside` kind blocking a whole-declaration
   Solved. T-R0b §11 item 4 notes that this makes any `Option(a)`
   use Unsupported, and E17, E20-E23 mark effect arguments, handlers
   and `fail`. So step 4 cannot land without refusing programs that
   compile today, unless kinds are exempted with arguments, and no
   argument exists. No R0 document says what happens at the switch;
   §18.69 Q9 only asks that the window be specified and tested. This
   plan makes it G-switch's question, with census evidence (3.5).
2. **The step 4/5 window cannot be closed by implementation.** Step
   5's trusted rules and refuter need P-C1 and P-CX, which are proof
   work and unauthorized. "Land 4 and 5 together" therefore means
   waiting for proofs, and §10's "No order keeps today's false
   contradictions" holds only with a window.
3. **Unaudited effect refusals during migration.** T-R0a §3.2 makes an
   effect refusal class f unless shown not to read record metas,
   while T-R0e §3.2's last row keeps effect codes "unchanged"
   (class a) except where a check reads a solver-selected type. It
   is ambiguous which applies before the audit. This plan keeps
   today's codes until G-effects (Tasks 0.5, 2.3).
4. **Second spread placement.** T-R0a §10 step 4 says the plan places
   it, while T-R0e §1.5 and §6 put it at 6f, after step 6. This plan
   follows T-R0e (Task 6.5) and gates it on G-switch, since it
   depends on `decide` being the user-visible path.
5. **Removing Resolve's body-type refusals needs G0's definedness
   check** (Task 4.2). The documents argue the move but do not name
   this precondition; without it an invalid lambda annotation could
   be Solved.
6. **`ValidR`'s ground rule is unfixed at declared types holding
   functions**, yet Sig10 records `pr ⟦R⟧` for `main` in every
   program. Until G-ValidR, G0 cannot judge some programs'
   requirement atoms. Task 4.2 refuses them visibly instead of
   guessing.

Re-verified against 76cd373: two former items are resolved and
dropped. `Inadmissible`'s `Int` is the callee's `VarId` in W §2.3 as
in T-R0a §6, and `ReCheckFailed` is now T-R0a's `EmissionFault`,
outside `InternalFault`. Items 1-6 above still hold at 76cd373.

Nothing found blocks writing the plan. Items 1 and 2 decide whether
