# Waxwing for VS Code (IDE001 stage 1)

Syntax highlighting only: a TextMate grammar and a language configuration for
`.wxw` files. There is no runtime code, no diagnostics and no language
server. The extension is private and is not published.

## Install locally

Run "Developer: Install Extension from Location..." in VS Code and choose
this directory (`editors/vscode`). Alternatively symlink it:

    ln -s "$PWD/editors/vscode" \
      ~/.vscode/extensions/waxwing-local.waxwing-vscode-0.0.1

then reload the window. Recent VS Code versions may ignore a bare symlink
unless the extension is also listed in `~/.vscode/extensions/extensions.json`;
if the language does not appear, use Install Extension from Location.

## What is highlighted

- Reserved words, as the lexer reserves them (`Format.Lex.Chars.reserved`):
  control (`if then else match with handle defer resume`), declarations
  (`fn type effect handler let ctl`), `true`/`false`, the built-in types
  `Int Bool Unit Text`, and the wildcard `_`. `pure`, `nofail` and `fail` are
  contextual (ordinary names to the lexer) and are always highlighted.
- Uppercase names as types, constructors and effects; lowercase names as
  values; integers, with a leading `-`.
- Operators `+ ++ == != < <= > >= -> => |> ...`, `=`, and the separators
  `: , ; |`.
- Text literals, nested: ordinary `"..."` with the escapes `\n \t \r \" \\
  \$ \u{...}`; `${...}` holes holding ordinary source, recursively; raw
  `#"..."#` literals closed only by a quote and the same count of `#`s, with
  `\#` escapes and `$#{...}` holes at that count; `"""` blocks and
  `#"""..."""#`. Invalid escapes are marked `invalid.illegal`. A hole in a
  one-line literal ends at the end of its line, as in the lexer.
- Not highlighted, because the language has none yet: comments (CMT001).

## Limits of TextMate

- Escapes and holes of a raw literal depend on its `#` count, which a rule
  cannot read from its parent, so the grammar has one generated rule per
  count 0 to 16. Longer runs close correctly (by back-reference) but have no
  inner escapes or holes.
- Escape validity is checked by pattern only: surrogates and values above
  10FFFF in `\u{...}` are not marked. A `"` followed by more `#`s than the
  literal opened with is not flagged.
- No semantic information: a lowercase name is never told apart as a
  function, a parameter or a field.

## Maintaining the grammar

`syntaxes/waxwing.tmLanguage.json` is generated by
`node scripts/editor-grammar-generate.mjs`; do not edit it by hand.
`npm run verify` runs `test/editor-grammar.test.mjs`, which fails if the
file differs from the generator or if its keyword set differs from the
lexer's reserved words.

Tokenization snapshots (`snapshots/`) cover every `examples/*.wxw` and
`fixtures/text-literals.wxw`. They need two packages that are not
repository dependencies, so the check is opt-in and is not part of verify:

    npm install --no-save vscode-textmate vscode-oniguruma
    node scripts/editor-grammar-snapshots.mjs            # compare
    node scripts/editor-grammar-snapshots.mjs --update   # after review

`WAXWING_GRAMMAR_MODULES=<dir>` points the script at another directory that
holds `node_modules`.
